## Navigation: a local tree, not upstream's router

Upstream's example is an Expo Router app. `app/index.tsx` is a list of
`<Link href="/(examples)/…">` and `app/_layout.tsx` is a router `Stack`; both
resolve against *this* app's router once vendored, so neither is mounted.

What makes a clean host possible is that **none of the 19 example screens import
expo-router**. They are plain components. So `rive-demo-host.tsx` supplies its own
list-and-detail navigation and mounts each screen unmodified — the same approach
as the HeroUI Native entry's own nav tree.

Both router files are still vendored and listed in the source viewer, because
they are where upstream shows how the example is wired together.

## The interesting part: `.riv` files are native resources

Most of the screens load animations by `resourceName={'avatars'}`. That is not a
Metro asset — it is a *native* lookup, asking the app bundle for `avatars.riv`.
On iOS the file must be a member of the target's "Copy Bundle Resources" phase;
on Android it must sit in `res/raw/`. Upstream does this by hand in its
checked-in Xcode project, which is not an option here: `ios/` is gitignored and
regenerated by every prebuild.

So `plugins/with-rive-assets.js` does it:

1. `withDangerousMod` copies `source/official/ios/Assets/*.riv` into `ios/RiveAssets/`.
2. `withXcodeProject` adds each file to the app target's Resources build phase
   via `IOSConfig.XcodeUtils.addResourceFileToGroup`.

A note for anyone extending it: `xcode`'s own `project.addResourceFile` fails here
with `Cannot read properties of null (reading 'path')` — it expects a group that
already has a path, and a freshly created one does not. Expo's
`addResourceFileToGroup` helper creates the group and wires the build phase
correctly, and is what the plugin uses. The plugin also skips files already in the
project, because adding a path twice produces a "multiple commands produce" build
failure on the next build rather than at prebuild time.

Only the **six** resources the vendored screens actually name are copied —
`avatars`, `out_of_band`, `quick_start`, `rating`, `rewards`, `skills_listener` —
not all two dozen upstream ships, to keep the diff proportionate.

`SourceProp.tsx` additionally uses `source={require('../../assets/rive/avatars.riv')}`,
which *is* a Metro asset. That path needed `riv` added to `assetExts` in
`metro.config.js`, alongside the existing `db`, `lottie`, and `html`.

**Android is not wired up.** The plugin handles iOS only. Doing Android means
copying the same files into `android/app/src/main/res/raw/`, which is a
straightforward addition to the same plugin but was not needed for the iOS
verification this entry was built against.

## Local adaptations to vendored source

None. Every vendored file is byte-identical to upstream. All the adaptation lives
in the host and the config plugin.

## What runs on the simulator

The animations render and the state machines run. Three screens depend on the
network — `Http`, `MeshExample`, and parts of `QuickStart` and
`ErrorHandledManually` load `.riv` files from `public.rive.app` — so they show
their error states offline, which is upstream behavior and in two cases the point
of the screen. `ErrorNotHandled` is *designed* to surface an unhandled error; it
is not a defect in the demo.
